# CloakProxy — User Guide

This walkthrough covers every feature of the workbench, in the order you would use them during a real incident ("I found a leaked key in a billing file and I still need AI help refactoring it").

## 1. Opening the workbench

Three ways:

| Entry point | How |
|---|---|
| Toolbar | Click the CloakProxy action icon (or `Ctrl+Shift+K`) — `chrome.sidePanel.setPanelBehavior` opens the panel |
| Context menu | Select any text on any page → right-click → **Inspect & Refactor Safely in CloakProxy** |
| Direct | Paste or edit code inside the Side Panel workbench |

Context-menu captures work even when the panel is closed: the service worker stashes the selection in `chrome.storage.session` and the panel drains it on the next mount. Nothing is ever injected into the page you copied from — CloakProxy never touches third-party DOM (ChatGPT, Claude, Gemini web textareas, etc.).

## 2. The pre-flight card (top of the panel)

On mount, the panel probes Chrome's Built-in AI:

- `NANO 4 · AVAILABLE` — on-device inference is live; Stage 1B runs locally on Gemini Nano 4.
- `NANO 4 · DOWNLOADABLE` — one click downloads the model (~2 GB) with a live progress bar.
- `NANO 4 · UNAVAILABLE` — a non-blocking setup card lists the exact flags to enable. Every other flow remains fully testable; Stage 1B simply runs on deterministic heuristics.

## 3. Loading code

- **Samples bar** — three one-click fixtures: a Stripe live-key leak, a proprietary pricing algorithm, and a production `.env`. These are synthetic but realistic.
- **Paste/edit** — the raw input pane is a normal editor until you run the pipeline.

## 4. Cloak & Refactor — reading the glassbox HUD

Click **CLOAK & REFACTOR →** and watch the Stage Rail:

```
1A DETERMINISTIC EXTRACT → 1B NANO 4 CLASSIFY → 1C VAULT SWAP
→ LEAK GATE → CLOUD INFERENCE → RE-HYDRATE
```

### Pane 01 — Raw Local Input
Inline highlights over the raw text:

- red underline = `SECRET` (deterministic or LLM-flagged)
- violet underline = `PROPRIETARY_LOGIC`
- green underline = `SAFE` — intentionally left intact so cloud reasoning keeps semantic context.

### Pane 02 — Sanitized Cloud Packet
The exact bytes that will cross the wire, plus:

- **✓ 0 BYTES RAW PII** — the pre-flight assertion passed. If it ever fails you get a red `✕ LEAK GATE BLOCKED` card with the offending (redacted) previews, and **no cloud request is constructed**.
- **Bijective vault legend** — every `fn_*` / `str_*` / `ident_*` key with its classification and a redacted preview.
- **inferenceSource pills** — `CLASSIFY_LOCAL · ON_DEVICE · 58ms` etc., one per hybrid call with per-stage latency.

### Pane 03 — Re-Hydrated Output
The cloud response with all placeholders deterministically restored, plus:

- **✓ SYNTAX INTACT** — raw and sanitized both parse identically (acorn) for JS/TS inputs.
- **RAW CLOUD WIRE** (collapsible) — the untouched sanitized response, proof of what the model actually saw.
- A session title generated by `PREFER_ON_DEVICE` inference.

## 5. Compliance presets (Remote Config)

The header switcher flips live strictness — **STRICT SOC2 · CODE BALANCED · OSS PERMISSIVE**. It changes entropy thresholds, which detector rule sets are active, whether generic identifiers are classified, and how many Red-Team vectors run. The same parameter is also served from Remote Config, so you can change fleet behavior without shipping a new build. A `cloud_kill_switch` Remote Config parameter disables the cloud stage for everyone instantly.

## 6. Red-Team Probe

After a successful run, click **1-CLICK RED-TEAM PROBE**. Cloud Gemini is prompted as an adversary — prompt injection to extract vault keys, semantic reconstruction of the secret, business-logic reconstruction, correlation via identifier density, vault-key pattern abuse, endpoint inference.

Scoring is computed **locally**, never by the model:

```
score = 100 − 40·compromised − 20·partial − 10·(leaks>0)
```

- ≥ 90 → `FORTIFIED` · ≥ 70 → `RESILIENT` · below → `LEAKY`
- Each finding shows the vector, the outcome, and the adversary's guess in redacted form. A compromised guess is itself sensitive, so it is redacted before it is ever displayed or logged.

## 7. Air-Gap mode

Toggle **AIR-GAP** to pin every call to `ONLY_ON_DEVICE`:

- No cloud request object is constructed at all — not "sent later", never built.
- Ask **AIR-GAP LOCAL Q&A** questions about the raw code; answers stay on-device.
- Offline Remote Config uses the last activated preset; queued telemetry flushes when you reconnect (bounded queue, oldest dropped first).

## 8. Telemetry (what is and isn't stored)

Every hybrid call logs to Firestore under your anonymous UID: stage, mode, `inferenceSource`, model, latency, token estimates, status, preset. Red-Team runs log vector outcomes, the score and hashes.

Never stored: raw code, identifiers, vault originals, model guesses (un-redacted), emails, any PII. The server-side ruleset rejects documents containing secret-shaped strings even if a modified client tried to write them.

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| Notice: *Anonymous auth failed (auth/admin-restricted-operation)* | Firebase Console → Authentication → Sign-in method → enable **Anonymous**, then reload the panel |
| Notice: *must enforce Firebase App Check* on first AI call | Register your debug token: Console → App Check → Apps → Manage debug tokens |
| `PERMISSION_DENIED` on model calls | Run `npx -y firebase-tools@latest init ailogic` against the project |
| `USER_PROJECT_DENIED` / *The caller does not have permission* | Link a billing account (Blaze plan) in Firebase Console → Usage and billing — AI Logic requires it |
| `NANO 4 · UNAVAILABLE` | Enable the two `chrome://flags` listed on the card and relaunch Chrome |
| Extension ID changed | Your local `extension_public_key.txt` is missing during build — the pinned `key` field was skipped |
| Cloud stage silently skipped | Air-Gap is on, `cloud_kill_switch` is active, or the preset has `allowCloud: false` |
